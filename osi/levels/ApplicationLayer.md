# 🌐 Уровень L7 (Прикладной) под микроскопом
Прикладной уровень (Application Layer) — это самый верхний уровень модели OSI. Здесь сетевые данные окончательно превращаются в понятные для программ форматы (HTML, JSON, бинарные стримы). Для веб-разработчика это главный слой абстракции, где происходит вся бизнес-логика, маршрутизация и обеспечение безопасности приложений.

Предоогаю разобрать внутреннее устройство, анатомию запросов и ключевые протоколы, которые живут на уровне L7.

## 1. Анатомия HTTP-запросов и ответов

Протокол [HTTP (HyperText Transfer Protocol)](../../http/history-of-http.md) работает по текстовой текстоцентричной схеме «Запрос-Ответ» **(Request-Response)** через TCP-соединение. Он полностью состоит из понятных строк текста **(plain text)**, разделенных символами переноса строки.

### Cтруктура HTTP-запроса (Request)
Любой HTTP-запрос, который ваш браузер или мобильное приложение отправляет на NestJS, состоит из трех частей:

*  Стартовая строка (Start Line): Содержит HTTP-метод, URI (путь) и версию протокола.

    * Пример: POST <span style="color: green">***/api/v1/users HTTP/1.1***</span>

* Заголовки (Headers): Метаданные в формате Ключ: Значение. Они передают информацию о типе контента, кодировке, куках и клиенте.

    * Host:<span style="color: orange">***api.mysite.com***</span> — целевой домен.

    * <span style="color: yellow">***Content-Type: application/json***</span> — указывает, что в теле запроса лежат данные в формате JSON.

    * <span style="color: yellow">***Authorization: Bearer***</span> <JWT> — токен для проверки прав.

* Тело запроса **(Body)**: Опциональное поле. Содержит сами передаваемые данные (JSON, XML или бинарный файл). Отделяется от заголовков пустой строкой.

### Структура HTTP-ответа (Response)
Когда NestJS обработал запрос, он возвращает ответ в похожем формате:

* Строка статуса (Status Line): Версия протокола и числовой код ответа с текстовым пояснением.

    * Пример: ***HTTP/1.1 200 OK*** или ***HTTP/1.1 404 Not Found***

* Заголовки (Headers): Метаданные сервера.

    * ***Server: nginx/1.25.0*** — какой веб-сервер отдал ответ.

    * ***Cache-Control: no-cache*** — инструкции браузеру по кэшированию.

* Тело ответа (Body): Данные, которые отрисует фронтенд (HTML-код страницы или JSON-объект).

<a id="HTTPCodes"></a>
## 2. Коды ответов HTTP (Категории)
Коды ответов классифицированы по первой цифре, что позволяет балансировщикам (Nginx/HAProxy) принимать решения о маршрутизации, даже не читая тело ответа.

* ***1xx*** — Информационные: Запрос принят, процесс продолжается (например, 101 Switching Protocols при переходе на [WebSockets]()).

* ***2xx*** — Успешно: Запрос был успешно получен, понят и обработан (самый частый — 200 OK, а при создании сущности в [БД]() — 201 Created).

* ***3xx*** — Перенаправление (Redirect): Клиенту нужно сделать дополнительный запрос для завершения операции (например, 301 Moved Permanently для редиректа на HTTPS).

* ***4xx*** — Ошибка клиента: Запрос содержит синтаксические ошибки или не может быть выполнен (например, 400 Bad Request — не прошла валидация полей, 401 Unauthorized — нет токена, 403 Forbidden — токен есть, но нет прав администратора).

* ***5xx*** — Ошибка сервера: Сервер потерпел неудачу при обработке корректного запроса (например, 500 Internal Server Error — упал Node.js процесс, 502 Bad Gateway — Nginx работает, но умер запущенный за ним NestJS).

<a id="AnotherProtocols"></a>
## 3. Другие ключевые протоколы уровня L7

Помимо HTTP, на прикладном уровне развернута работа других важнейших технологий современного веба:

### [WebSockets (WS / WSS)](../../protocols/Ws.md)
Классический HTTP не умеет присылать данные с сервера без явного запроса от клиента. WebSockets решает эту проблему, обеспечивая полнодуплексную (двунаправленную) связь через один постоянный TCP-сокет.

* Как это работает: Клиент делает обычный HTTP-запрос со специальными заголовками Upgrade: websocket и Connection: Upgrade. Происходит «рукопожатие» (Handshake), HTTP-сессия закрывается, а сокет переходит в режим WebSocket, где и сервер, и клиент могут слать байты друг другу в любой момент времени (идеально для чатов, биржевых котировок и онлайн-игр).


### [gRPC (Google Remote Procedure Call)](../../protocols/gRPC.md)

Современный высокопроизводительный фреймворк для общения между микросервисами.

* Как это работает: Вместо передачи тяжелого и неоптимального текста JSON через HTTP/1.1, gRPC работает строго поверх HTTP/2 и использует бинарный формат сериализации данных Protocol Buffers (Protobuf). Данные сжимаются до минимальных размеров и летят между серверами с экстремальной скоростью, поддерживая строгую типизацию контрактов.


### [DNS (Domain Name System)](../../networks/networks.md)
Хотя DNS часто воспринимается как инфраструктурная утилита, на самом деле это классический протокол прикладного уровня, работающий по сети через UDP-порт 53 для мгновенного резолва доменных имен.

<a id="SecurityHeaders"></a>
## 4. Заголовки безопасности на уровне L7
Защита веб-приложения от взлома на уровне браузера во многом зависит от того, какие L7-заголовки ваш Nginx или NestJS (например, через библиотеку helmet) отдает в HTTP-ответе.

Content Security Policy (CSP)
Один из самых мощных заголовков защиты. Он жестко объявляет браузеру список доверенных доменов, с которых разрешено загружать скрипты, стили или изображения.

```http
Content-Security-Policy: default-src 'self'; script-src 'self' https://trustedscripts.com;
```

От чего защищает: Полностью блокирует XSS-атаки. Даже если хакер сможет внедрить вредоносный тег 
```script
<script src="hack.com/malware.js">
``` 
в вашу HTML-страницу, браузер прочитает CSP заголовок, увидит, что домен hack.com не входит в белый список, и заблокирует выполнение кода.

HTTP Strict Transport Security (HSTS)
Заставляет браузер автоматически и принудительно переводить любые запросы к сайту на защищенный протокол HTTPS, даже если пользователь вручную ввел http://.

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

От чего защищает: Защищает от атаки SSL Stripping (разновидность Man-in-the-Middle), при которой злоумышленник перехватывает трафик в локальной сети и пытается откатить безопасное HTTPS-соединение до открытого текстового HTTP.

X-Frame-Options
Указывает браузеру, разрешено ли открывать ваш сайт внутри тегов 
```iframe
<iframe>
```
 на чужих ресурсах.

 ```http
 X-Frame-Options: DENY
 ```

 От чего защищает: Защищает от Clickjacking (Кликджекинга) — атаки, при которой ваш сайт прозрачным слоем накладывается поверх фейковой страницы злоумышленника, заставляя пользователя совершать скрытые целевые действия (например, нажимать на кнопки перевода денег).

## Резюме L7 уровня:
L7 — это слой, где сеть встречается с кодом приложения. Понимая структуру HTTP-пакетов, особенности веб-сокетов и механизмы заголовков безопасности, разработчик может проектировать устойчивые к нагрузкам микросервисы и эффективно настраивать правила фильтрации трафика на уровне балансировщиков.
